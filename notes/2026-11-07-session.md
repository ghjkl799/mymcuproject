## Outcome

| Function | Hardware | Pin | Page / API | Status |
|---|---|---|---|---|
| Temp + humidity | DHT22-M module | D2 (GPIO4) | Climate tiles, `GET /api/sensor` | verified (~26 °C / ~49 %) |
| Relay | RELC-1CH-5V-UNI | D5 (GPIO14) | On/Off/Toggle, `GET/POST /api/relay` | verified (meter) |
| PWM channel 1 | PWMMOS-4 | D1 (GPIO5) | Slider 0–100 %, `GET/POST /api/pwm1` | verified (meter + fan) |
| Built-in LED | on board | D4 (GPIO2) | On/Off/Toggle, `GET/POST /api/led` | verified |

## Wiring

Breadboard: one side's rails = 3V3, other side's = VIN (5 V), both − rails = GND (linked).

```
DHT22-M           +  -> 3V3        OUT -> D2         - -> GND
RELC-1CH-5V-UNI   DC+ -> VIN (5V)  IN  -> D5         DC- -> GND     jumper: H (high trigger)
PWMMOS-4 ch1      PWM1 -> D1       GND1 -> ESP GND
                  DC+/DC- -> load supply (9 V battery / 12 V), NOT connected to ESP GND
                  load on OUT1+ / OUT1- (low-side switch)
Fan EFB0412HHD    red -> OUT1+     black -> OUT1-    white (tach) -> unconnected
```

## Decisions

- **Page served by the board itself** (same origin, no extra host). HTML as PROGMEM string; move to LittleFS if it grows.
- **API + page split**: page uses `fetch()` on relative URLs, polls every 2 s. State changes are `POST`.
- **Secrets outside the repo**: private Arduino library
  `%USERPROFILE%\Documents\Arduino\libraries\Secrets\Secrets.h` (`WIFI_SSID`, `WIFI_PASS`), `#include <Secrets.h>`.
  Never read or printed by Claude; SSID/password never printed to serial. No Wi-Fi fallback (by choice).
- **Serial at 74880 baud** so the ESP8266 ROM boot log and sketch output are both readable.
- **Sensor read in `loop()` every 2.5 s**, API serves the cached value (requests never wait on the DHT22).
- **Outputs driven OFF first in `setup()`** (relay, PWM) before Wi-Fi.
- LED and relay share one `Output` struct; PWM has `PwmOutput`. New channels = one line + registration.

## Findings / gotchas

- Board: NodeMCU ESP-12E, CP2102 on **COM3** (COM5/6 are Bluetooth). FQBN `esp8266:esp8266:nodemcuv2`.
- **Upload must use `:baud=115200`** — default speed fails mid-flash.
- **`arduino-cli upload` exits 0 even on failure** — `flush.cmd` checks for `Hash of data verified`.
- **COM3 is exclusive** — close the serial monitor before uploading. Opening the port resets the board.
- Garbage at boot = ROM bootloader at 74880 baud (now readable); `rst cause:` 2 = reset pin, 4 = watchdog.
- `%~dp0` ends in `\`, which escapes the closing quote in cmd — strip it first.
- Arduino preprocessor inserts auto-prototypes before the first function → **declare structs before any function**.
- NodeMCU LED is **active LOW**.
- DHT22: ≥ 2 s between reads; power from 3V3 (module pull-up would put 5 V on the GPIO from VIN).
- Relay contacts are dry (no voltage of their own): test with Ω (COM–NO closes when ON), or 5 V → COM and
  measure NO vs GND. **Never** put 5 V on NO and GND on COM — that's a short when the relay closes.
- **PWMMOS-4** (from hestore datasheet/schematic): 4 ch, 60N03 MOSFETs, LTV217 opto inputs, DC+ 3.7–27 V,
  10 A/ch, input 3–20 V. 3.3 V input works (IN LED faint) and fully switches the output.
  Gate turns off through 100 kΩ → slow → **PWM at 100 Hz**, not the 1 kHz default.
  Output is pulsed full DC+ voltage (meter shows average) — not a voltage regulator.
- Fan's white wire = tachometer output; unreliable while the fan's supply is PWM'd.

## Multimeter (DT830D) notes

- DCV: in parallel, pick the smallest range above the expected value (20 for 3.3/5/12 V). "1" = overrange.
- ACV: mains only; not needed in this project — be careful.
- DCA: in series; never across a voltage source; 10 A jack max ~10 s, move probe back afterwards.
